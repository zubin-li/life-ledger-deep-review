# Web Today 卡片化 — 可行性评估（2026-10-17，待用户确认，未授权实施）

基于：`.hermes/handoffs/LIFE_LEDGER_HISTORY_AND_REQUIREMENTS_2026-10-17.md`、当前代码只读检查、GridStack ADR（docs/third-party-notices.md）、四模型评审（2026-10-17-final-design-proposal.md）。

## 现状根因
- `public/widget-registry.js`：全部 7 个卡都声明 small/medium/large → 33 种组合，每种都要单独设计，没做完 → 乱码/溢出。
- `public/layout-engine.js`（1553 行自写）：12 列 x/y 坐标 + 碰撞；尺寸改变留空位，不同尺寸宽高规则不统一。
- Today 容器限宽 1120px、独立滚动容器带滚动条；外壳样式不是原版。
- 布局只存在本机浏览器，不同步。

## 方案
1. 每张卡只给有意义的尺寸（约 16 个变体，取代 33 个）：
   问候 1 / 心情 1 / 习惯 2（4 个、8 个）/ 每日日程 1 / 复盘(含专注切换) 1 / 专注 1 / 月历 1（通栏）/ 热力图 2 / 天气 2 / 照片墙 3 / 7 日节律 1。
2. 贴格子：保存“顺序 + 尺寸”，浏览器网格自动排；电脑 4 列、平板 2 列、手机 1 列同一顺序。
3. 拖动：SortableJS（MIT、3.1 万星、1.15.7、支持触屏和网格、移动 DOM 不用绝对定位，避开 GridStack 被否决的原因）。替换自写拖动/碰撞代码。保留按钮/键盘移动作为后备。
4. 外壳、配色、圆角、动效直接复用 main 原版代码；Today 与其他页同宽、整页滚动、无滚动条。
5. 卡片内部复用原版 3.5 的显示代码（已接回）+ 10/14 应用稿的新卡（天气、照片墙、热力图）。
6. 布局随账号同步（电脑浏览器之间一致），手机自动按同一顺序单列。

## 分阶段

|---|---|---|---|---|
| 1 视觉确认 | 用真实页面代码出每张卡每种尺寸 + 整页（浅/深、电脑/手机、编辑模式）截图与录屏 | 我 | 2–3 小时 + 你 1–2 轮 | 150–300 万（多为缓存重读） |
| 2 实现 | 换排版和拖动、去掉多余尺寸、外壳复原、测试 | 机械部分 Cursor 照截图写；视觉打磨我做 | 0.5–1 天 | 100–200 万；Cursor 用自己的额度 |
| 3 验收 | 你的真实数据副本，各宽度与截图并排 | 我先查，你确认 | 1–2 轮 | 50–100 万 |

数字是粗估，可能差一倍。开新对话可显著降低（本对话每步都重读长历史）。

## 做不到 / 限制
- 不做 Obsidian 白板式任意摆放：手机单列无法自动排好，成本高数倍。
- 手机上只能排顺序，不能并排摆。
- 每加一个尺寸变体都是一份设计 + 检查成本，所以尺寸只给照片、天气、热力图、习惯。
