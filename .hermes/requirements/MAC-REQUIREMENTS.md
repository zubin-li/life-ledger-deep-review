## 用户是谁、要什么（10/26 原话摘）
> 「我自己搭建好了我自己的个人站一个网页，我希望把它做成一个 App，然后这个 App 能跟网页一样，有原生的那种感觉，
> 各种交互动态都跟网页很接近，就是基本上是一样的。然后甚至比网页还要流畅。」
> 「给更多人，他可能根本不会 GitHub 的这些人，他们直接可以下载，可以使用，而他们用的大都是本地版…也保留那个网页版接口…
> 我自己平时用的肯定是联网的」
> 10/26 决定：「让 Tauri 这个方案直接开工」「苹果开发者账号不买…后面如果有不断的盈利再说」「联网模式…改为邮箱验证码登录」

## v2 做法（10/26）
- 网页文件不再为 Mac 改样式：Mac 专用的 `desktop/mac/shell.css|js` 由应用注入（本机窗口 + 联网窗口），网页本身从不加载。
- 首轮代码备份：`ll-mac-qa/backup/round1/`。
- 验收：`ll-mac-qa/macgate2.mjs`（3 语言 × 明暗 × 3 尺寸 × 6 页，与线上网页逐像素对照）+ `realqa.sh`（真窗口，AppKit hit-test 每个按钮）。

## 版本号规则（10/28「以后给新版都加个版本号，不要跟之前的旧版混淆了」）
- 每次交给用户检查的新版本都升一个版本号（package.json / tauri.conf.json / Cargo.toml / sw.js / index.html ?v= / CHANGELOG 同步），不在同一版本号上重复改。
- 版本号要看得见：Mac 启动窗口标题下显示 "Version x.y.z"；网页和应用里 设置 最底部显示 "Life Ledger x.y.z"。
- 交付 Mac 预览前：重建包、确认没有旧实例在运行、确认包内版本号 = 新版本号、清掉记住的工作区（让启动窗口出现）。

## 应用内更新（11/02「推送一下更新，然后我这边软件会收到…推送更新」）
- 3.0.2 起：启动时 + 每天检查 https://github.com/zubin-li/life-ledger-deep-review/releases/download/mac-updates/latest.json；弹窗「更新并重启 / 稍后」，同意后才安装；菜单 Life Ledger → 检查更新…、设置 → 检查更新。
- 签名密钥：~/.tauri/life-ledger-updater.key（无口令，仅本机）+ GitHub secret TAURI_SIGNING_PRIVATE_KEY；公钥在 tauri.conf.json。丢失密钥 = 所有人需手动重装一次。
- 发布（11/02 用户「为什么要等待 GitHub 自己构建？」）：推 tag 后不等 GitHub 的 macOS 机（连续三次排不上），直接本机后台构建：`ll-mac-qa/release-mac-local.sh <web> <mac>`（同一 tag 提交、同一更新密钥，先传包后传 latest.json），然后取消排队的 macos-artifacts。
- 上传后 GitHub 下载地址有约 1–3 分钟缓存：用 `ll-mac-qa/feedcheck.mjs` 复核直到版本号对且签名有效，再通知用户。
