# Life Ledger 3.2 failure audit

## Verdict

3.2 is not a cache problem. It is a real build, but it changes mostly **interaction plumbing** while preserving the same first-frame product composition. That is why the user experiences it as “almost the same app.”

## Evidence from `565e4db..3654c31`

- `public/interaction.js` adds about 399 lines for the command palette, moving selection indicators, rolling numbers, disclosure state, and short view-entry transitions.
- `public/styles.css` changes the Today page from two large columns into a 12-column grid, but keeps the same permanent set of zones: habits, mood, reflection, photos, plus the existing right Focus rail.
- `public/index.html` mostly moves the existing Today modules into cards. It does not replace the information architecture.
- Review gains a trend, heatmap, and comparison area, but remains a dashboard assembled from the same shell and visual primitives.
- The committed “prototype screenshots” are generated by `docs/prototypes/phase-3-2-proportions.html`, a separate simplified HTML mock, not screenshots from the built Tauri application.
- The acceptance contract requested a real interaction demo, but the final commit contains no new real-app motion recording.

## Why the reference video did not carry through

The video was reduced to six mechanisms and most were rejected or applied only at the navigation chrome level. The implementation adopted a sidebar pill and `Cmd+K`, but did not adopt the reference’s more important compositional qualities:

- a strong focal surface instead of several equal-weight columns;
- context that unfolds from the user’s selection;
- stable spatial continuity between overview and detail;
- dynamic reconfiguration of content, not just a fade when switching pages;
- fewer simultaneously visible functions.

The result has “motion features,” but the product does not **feel dynamic** because the layout itself does not respond to the user’s task.

## Root design problems to remove

1. **Permanent three-band composition.** Sidebar + crowded canvas + permanent Focus inspector makes the window look like a web admin dashboard.
2. **Card soup.** Habits, mood, reflection, photos, focus, events, and metrics compete at the same visual level.
3. **No primary task per screen.** Today tries to be habit list, journal, photo library, mood check-in, and focus timer simultaneously.
4. **Motion is cosmetic.** A sliding pill and rolling number do not explain object continuity or hierarchy.
5. **Prototype validation is disconnected.** A separate static HTML mock can pass visual review while the real Tauri app remains largely unchanged.
6. **Feature preservation was interpreted as simultaneous visibility.** Data and capabilities must remain, but they do not all need to be visible in the same first frame.

## Non-negotiable correction

Phase 3.3 must be an information-architecture reset, not another refinement pass. The old Today grid and permanent right inspector must be removed or fundamentally replaced. Validation must come from the actual built application.
